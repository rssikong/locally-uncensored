# `.fork/` — what this fork changes on top of upstream

The fork tries to own as little as possible of upstream. Everything here is the
machinery that keeps that true.

```
patches/    the few files upstream also owns, as diffs against upstream/master
README.md   this file
```

## The six patches

| Patch | File | Why |
|---|---|---|
| 01 | `src/main.tsx` | one call to `applyDocumentLocale()` before React mounts |
| 02 | `src-tauri/tauri.conf.json` | the updater endpoint and public key point at **this** repository |
| 03 | `src/stores/updateStore.ts` | the update check asks **this** repository |
| 04 | `src/components/layout/UpdateBadge.tsx` | the "view release" link points at **this** repository |
| 05–06 | two guard tests | they walk every string under `src/`; the generated dictionary has to be exempt or it is read as UI copy |

> `playwright.config.ts` used to be a seventh patch (it started the e2e web
> server in English and retried two geometry specs). It was **dropped on
> 3.0.8**: this fork no longer runs e2e, and upstream rewrites that file often —
> 3.0.8 turned `webServer` into an array for the mobile project, which is
> exactly the change that made the patch stop applying. One fewer file that can
> block a sync.

Everything else the fork adds is a **new file**: `src/lib/i18n/*`, `scripts/i18n-*`,
`scripts/fork-patches.mjs`, `e2e/i18n-gaps.spec.ts`, `.github/workflows/watch-upstream.yml`,
`.github/workflows/release-zh.yml`, `src-tauri/tauri.zh.conf.json`, `I18N.md`.
New files cannot conflict.

> The updater keys have to sit in `tauri.conf.json` and not in an overlay:
> upstream's `release-dry-run.mjs` refuses a checked-in overlay that sets
> `plugins.updater`, and its dry run rewrites that file. `tauri.zh.conf.json`
> therefore carries only `createUpdaterArtifacts` and the Windows installer
> languages.

## When a merge conflicts

`watch-upstream.yml` takes upstream's side for every conflicted file and then
replays these patches with `git apply --3way`. Three outcomes:

- patch applies → merged, checked, pushed;
- patch already present (the file merged but kept our hunk) → fine;
- patch does not apply → **nothing is pushed and nothing is released**. The fork
  keeps the last good version, and an issue says which patch failed.

## After upstream changed one of those six lines

Fix the file by hand, then regenerate the patch set:

```powershell
node scripts/fork-patches.mjs --check        # what is out of date?
node scripts/fork-patches.mjs --regenerate   # rewrite patches from the tree
git add .fork/patches
```

`--regenerate` diffs the working tree against `upstream/master`, so the patch is
always "what this fork adds on top of the current upstream file". Make sure
`git fetch upstream` is current first — a stale base produces a patch that
replays stale lines.

## What this directory is not

It is not a patch of the whole app, and it is not a git branch. The translation
itself lives in `src/lib/i18n/zh-CN.ts` and is regenerated by
`scripts/i18n-apply.mjs`; it does not appear here.
